# 2.5 API Design Document

## Section 1: Overview

The popoWebApp API is built on Google Apps Script (GAS) and runs entirely within the GAS sandbox. There is no REST endpoint in the traditional sense. Instead, the client invokes server-side functions through two mechanisms:

1. **`google.script.run`** — An asynchronous RPC mechanism provided by GAS. The client calls a named server function with positional arguments. The function runs on the server and returns a JSON-serializable value to the client via a success callback. Errors are delivered via a failure callback. This is the primary data API used by all authenticated CRUD operations.

2. **GET/POST HTTP handlers** — The `doGet(e)` and `doPost(e)` entry points handle page rendering and form-based actions respectively. GET requests with an `?action=` parameter return JSON data. POST requests with an `?action=` parameter handle state-mutating operations that originate from HTML form submissions or `fetch()` calls.

Because GAS renders web apps inside nested sandboxed iframes (`#sandboxFrame` → `#userHtmlFrame`), all client-side code must traverse these frames for DOM interaction. The `google.script.run` mechanism handles this automatically but imposes restrictions: base64-encoded images cannot be embedded directly in `<script>` tags (the Caja sanitizer strips them), and all RPC calls are inherently asynchronous with no request ordering guarantee beyond per-call callbacks.

Sessions are managed via tokens stored in `CacheService.getScriptCache()` with a 12-hour TTL. The client persists the token in `localStorage` as `popo_token`. All mutations to the Google Sheet database are protected by `LockService.getDocumentLock()` with a 30-second timeout to prevent write conflicts under concurrent access.

## Section 2: Authentication & Session API

| Function | Parameters | Returns | Auth | Description |
|---|---|---|---|---|
| `serverLogin` | `username: string`, `password: string` | `{ token, session }` or `{ error }` | **Public** | Authenticates a user by username/password. On success, creates a session in CacheService and returns the token and session data. Updates `last_login_at` on the user record. |
| `serverChangePassword` | `token: string`, `old_password: string`, `new_password: string` | `{ ok: true }` or `{ error }` | **Token** | Validates old password, then rehashes with a new salt. Clears `must_change_pwd` flag on success. |
| `serverLogout` | `token: string` | `{ ok: true }` | **Token** | Removes the session entry from CacheService. |
| `serverGetCurrentUserProfile` | `token: string` | `{ user_id, username, full_name, role, avatar, school_name }` or `{ error }` | **Token** | Fetches the current user's profile. If the avatar is a Google Drive URL, the image bytes are fetched and returned as a base64 data URI (workaround for Caja sanitizer). |
| `serverEditProfile` | `token: string`, `full_name: string` | `{ ok: true }` or `{ error }` | **Token** | Updates the user's display name. Also updates the cached session. |
| `serverUploadAvatar` | `token: string`, `base64Data: string` | `{ ok, avatarUrl }` or `{ error }` | **Token** | Uploads a base64-encoded image to Google Drive, sets sharing to anyone-with-link, and stores the URL as the user's avatar. Deletes any previous Drive-hosted avatar. Maximum payload: 500 KB. |
| `serverRemoveAvatar` | `token: string` | `{ ok: true }` or `{ error }` | **Token** | Removes the user's avatar. Trashes any Drive-hosted avatar file and clears the avatar field. |
| `getChangePasswordHtml` | `token: string` | `string` (HTML) | **Token** | Returns the rendered HTML for the change-password page. |
| `serverDeleteUser` | `token: string`, `user_id: string` | `{ ok: true }` | **Admin** | Permanently deletes a user. Prevents self-deletion. |

When `?api=` is present in a GET request, `handleTestApi(e)` is invoked. This is only available when `DB_SHEET_ID` is not set (i.e., during local testing). It exposes CRUD operations for test data seeding and cleanup, with all operations strictly requiring `test_` prefixed IDs.

## Section 24: Auth Requirements Summary

### Auth Levels

| Level | Description | Scope |
|---|---|---|
| **Public** | No token required. Accessible without authentication. | Login page, setup wizard, `serverLogin`, `wizardCreateDatabase`, `wizardSaveSchoolInfo`, `isFirstRun` |
| **Token** | Valid session token required (`session` object with `user_id`, `role`, etc.). | Most read/write operations. Teachers can access data for (class, subject) pairs where they are enrolled. |
| **Admin** | Valid session with `session.role === 'admin'`. | All `admin_*` pages, user management, enrollment CRUD, workload, audit, indicators CRUD, classes CRUD, subjects CRUD, weights write |

### Teacher-Scoped Access Pattern

For classroom-level operations (attendance, formative, summative, characteristics, read-think-write, students, report), the server enforces this authorization logic:

```
can_edit = (session.role === 'admin') || 
           Enrollments.filter(e => e.class_id === class_id && 
                                   e.subject_id === subject_id && 
                                   e.teacher_user_id === session.user_id).length > 0
```

If `can_edit` is `false`, the data is still returned (for read-only viewing by unauthorized teachers is prevented at the page routing level), but write operations will throw an authorization error. For student lists, the check also allows the homeroom teacher of the class:

```
can_edit = (session.role === 'admin') || 
           (cls.homeroom_teacher_user_id === session.user_id)
```

### Session Lifecycle

1. **Login**: `serverLogin()` → SHA-256 hash of `(password + salt)` → on match, generate 40-char random token → store `session_{token}` in `CacheService.getScriptCache()` with 12-hour TTL → return `{ token, session }` to client.

2. **Request**: Client sends `token` as the first argument to every `google.script.run` call (or via `?token=` query parameter for GET actions). Server calls `getSession(token)` to deserialize the cached session. If the session is expired or missing, the function throws an authentication error.

3. **Logout**: `serverLogout(token)` → removes `session_{token}` from cache.

4. **Session refresh**: Profile edits (`serverEditProfile`, `serverUploadAvatar`, `serverRemoveAvatar`, `serverChangePassword`) update the cached session in-place to avoid stale data.
